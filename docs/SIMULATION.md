# 仿真对话模式

在「实例 → 对话模式」展开卡片后，打开「仿真模式」。对话模式、群聊参与策略、平台、模型和人设默认折叠，只展示当前状态；参与策略放在人设设置前。已有实例默认仍是助手模式。仿真模式是实例的参与方式，复用现有 `BuiltinAgent`、工具循环、插件钩子和持久化会话，不是另一个 Agent 实现。

模型必须支持并启用工具调用。没有自定义群回复规则时，仿真使用自己的参与预设，不继承全局助手的「总是回复」：被 @ 时关注，其他群消息以 15% 概率开始一次参与，交给模型判断是否值得接话。自定义「仅 @」「总是」「概率」「从不」仍有效；仿真概率策略下 @ 不受抽样限制，「从不」仍禁止群聊唤醒。

在「何时参与群聊」中可直接调整主动参与概率（0%–100%，步进 1%），使用仿真预设时也可直接拖动。修改后保存为当前实例的群回复规则；重新开启「使用仿真预设」恢复 15%。0% 只阻止未被 @ 的新参与，100% 表示每条消息都有机会进入参与判断，都不强制模型发言。

开始监听后，平台投递的后续消息无需通过第二次唤醒判断。完整群消息平台支持不带 @ 的接话；QQ 官方群聊只投递 @ 消息，因此后续仍需 @。这与模型判断是否说话是两层不同的决定。

## 对话如何推进

1. 消息先经过实例门禁、插件预过滤和命令处理。未唤醒时，群消息进入已有的短期群观察记录。
2. 唤醒后，同群消息按短暂安静期合并成一批，持续有人说话时也不会无限等待。每条消息保留自己的身份、消息 ID 和媒体内容。
3. 模型通过 `conversation_say` 发送一个短想法，每批最多一次；日常发言最多 120 个 Unicode 字符。超长内容会明确退回模型要求缩短，不截断、不拆分。群友明确要求详细解释、代码或长内容时才可用 `expanded: true`（仍有 8000 字上限）。可用本次参与见过的消息 ID 指定引用对象。
4. 模型通过 `conversation_wait` 结束本次内部推理，运行时监听新消息；新消息到来后继续同一会话。超时无人说话就安静结束，不定时唤醒模型自言自语。
5. `conversation_leave`、未选择继续监听、达到时限或发言上限，都结束本次参与。普通模型结束语和思考内容不会发到聊天平台。

不模拟打字、不按换行拆分回复，也不自动引用触发消息。工具生成的图片或文件仍在内部轮次结束后按原有媒体规则发送，占用发言额度。插件的预过滤回复、命令回复和平台通知反应保留原有语义。

群聊与频道使用共享会话；助手模式原有的「按成员／按群」和「观察群聊」设置保留，切回助手模式后继续适用。私聊保持独立。仿真会话使用独立、按平台隔离的命名空间；不同平台的同号群不会串话，切换模式也不会合并已有会话。附加对话规则与人设、仿真开关独立：开启仿真自动勾选规则，关闭仿真保留规则状态；普通助手模式也可单独使用规则。可以选择已有角色或填写自己的提示词，也可关闭默认行为规则，但显式发言协议始终存在。默认规则强调接话、倾听、判断对象和话题、允许沉默，避免无关总结、客服套话、捏造经历或故意答错。

## 可设置项

保存在 `data/instances.json` 的实例中，也经实例 REST API 读写：

```json
{
  "conversation_mode": "simulation",
  "conversation_rules": true,
  "simulation": {
    "quiet_ms": 2500,
    "max_batch_ms": 10000,
    "listen_seconds": 30,
    "max_participation_seconds": 180,
    "max_messages": 3
  },
  "system_prompt": "你叫小夏，喜欢天文，语气平和，表达简洁。"
}
```

| 配置 | 含义与边界 |
| --- | --- |
| `quiet_ms` | 最新消息后等待的安静期，0–30000 毫秒 |
| `max_batch_ms` | 一批消息最多等待多久，100–60000 毫秒，不小于安静期且不超过参与总时限 |
| `listen_seconds` | 一次监听的上限，1–120 秒；模型可以选择更短时间 |
| `max_participation_seconds` | 含等待、准备和模型调用的一次参与总时限，10–600 秒，不小于监听上限 |
| `max_messages` | 一次参与最多尝试发送 1–20 条消息；发送失败也占额度，避免不确定回执引起重复发送 |
| `conversation_rules` | 顶层独立开关，是否附加对话行为规则；普通助手与仿真均适用 |

API 创建仿真实例时省略 `conversation_rules` 会默认开启；更新时省略则在进入仿真时开启，其他情况下保持原值。显式传布尔值可独立控制。旧文件里的 `simulation.behavior_prompt` 在读取时迁移：旧仿真保留其选择，旧助手不因原先不生效的默认值而自动开启规则；保存后只写新字段。预设不覆盖已保存的自定义时间和条数，可通过「恢复预设」恢复。

### QQ 官方被动回复

适配器通过通用 `PlatformAdapter::conversation_delivery_limits` 提供平台限制，核心不按平台名字分支。QQ 群聊和单聊每条入站消息最多尝试发送 5 条原生消息；文本和每个图片、语音、视频、文件分别计数。一次参与仍受实例的总条数限制（默认 3）。换引用对象不会重置额度，只有新入站消息提供新的被动回复上下文。

被动回复按原始消息时间计算有效期：群聊、文字频道和频道私信为 5 分钟，单聊为 60 分钟，预留 5 秒给发送队列和 HTTP。缺失／非法时间明确报错，过期停止本轮；不使用收到消息的时间冒充原时间，也不转为主动推送。频道采用每次最多 5 条的保守界限，两次发送至少间隔 1 秒。仿真不发送打字通知，避免占用单聊额度。平台在外部已用掉的额度和额外风控仍以实际发送结果为准，失败不自动重试。

模型当前轮会收到平台可见性、剩余额度和时限，不能声称看到了 QQ 官方没有投递的群消息。插件平台沿用已有通用发送契约和声明的可见性能力；特殊发送限制仍需适配器执行。

`/stop` 可打断正在生成或监听的参与。普通命令保持同一聊天内的顺序，不会被后续消息越过。配置变化在下次动作前校验；停用实例、切换会话或修改参与相关配置后，不再按旧配置发送。已经入发送队列的消息可能仍会送达，这是不可撤回的发送边界。

每个活跃聊天最多缓存 64 条经过过滤的待处理消息；溢出、取消或关机时尚未处理的消息记录到 `data/dead_letter`，不会无声丢弃或自动重试。运行时错误进入控制台日志，不绕过显式发言工具自动向群里发报错。模型和工具历史仍写入 `data/sessions.db`，重启可续接；监听计时器与尚未唤醒的观察记录不持久化。群观察仍沿用原有 30 条／30 分钟边界。

仿真轮次不借用某位群成员的管理员 Bash 身份；内置 Bash 在这种批量参与中不可用。控制台沙盒和插件主动 `RunAgent` 仍是普通单轮模型调用；需从实际平台入口验证合并、监听和显式发言。

## 平台身份与缓存

默认助手提示词改为自然、简洁、诚实的对话指导。当前轮明确区分平台、私聊／群聊／频道、群名、昵称、群名片与标识符：

- OneBot 和 Milky 的数字账号标注为「QQ号」，数字群标识为「QQ群号」。OneBot 异步补查群名，缓存五分钟；首次消息可能还没有群名，查不到时不猜测。
- QQ 官方机器人使用「用户OpenID／群OpenID」，不会把 OpenID 叫作 QQ 号；频道使用平台用户 ID 与频道 ID。
- 昵称、群名片、群名有数据时展示；账号和会话标识符继续受现有上下文开关控制。外部名称经长度限制和 JSON 引号处理，避免名字中的换行冒充其他标签。

工具定义与规则是静态的；时间、身份、剩余发言数、消息 ID 都进入当前轮。请求保持「排序后的工具 → 单条系统块（人设、模式规则、技能、摘要）→ 仅追加历史 → 当前轮」。一次内部轮次的系统钩子只调用一次，工具轮次和自动压缩复用相同前缀。更换人设、模式、规则开关或工具配置会有预期的缓存失效，不会通过滑动删除历史来伪装续聊。

## 验证与参考

构建后执行 `bun tools/verify-simulation.mjs`，脚本只在临时目录启动节点和本地假模型／OneBot／Milky，不读取生产配置。它检查两个开关独立保存、默认值、旧配置迁移、长消息限制、每批一次发言、批量消息、继续监听、沉默、独立人设、前缀稳定、身份标签、群与平台隔离、中断、上限、命令顺序、过载记录、热停用、总时限、重启续接和压缩前缀；请求和日志路径会打印出来。

参考 [qq-bridge](https://github.com/Derpyu520/qq-bridge) 的显式发送／等待与消息批处理，以及 [MaiBot](https://github.com/Mai-with-u/MaiBot) 的对话行动与外层等待调度。这里复用 Kanon 的会话、调度与工具契约，没有引入参考项目的运行依赖。
